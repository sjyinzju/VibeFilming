## D/E/G: new-project automation and limits

`POST /projects` uses the same FilmProduction/Application factory, canonical planning contracts, generated reference plan, independent quality DAG, providers, repair ledger, audio/post handlers and download resolver. `production_policy` configures planning human gates, candidate coverage and compute budget; it is not an LLM output. The installed/configured runtime profiles supply adapters from configuration. No film-specific Python script is required to advance a new project.

An installed model service and reachable configured endpoints are prerequisites. Deployment, tunnel diagnostics and the historical Hero migration remain operational scripts. The dedicated UI for role binding is still missing; its typed acceptance API is present. Unsupported shot complexity/provider capability, exhausted budgets, uncertain audio/performance judgments and final aesthetics can still require human action. Native multi-image Kontext and direct multi-reference H3 are not claimed; actual panel conditioning and reviewed boundary transport are declared capabilities. Live corrected repair/H3/VLM/candidate acceptance is outstanding; offline tests do not establish AI visual quality.
